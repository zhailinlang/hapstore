# 调试助手能力集成调研

> ⚠️ **本文结论已被更正版取代，请以 [DEBUG-HUB-PROPOSAL-v2.md](DEBUG-HUB-PROPOSAL-v2.md) 为准。**
>
> v1 的核心判断（「鸿蒙三方 App 不能安装 HAP」）已被 `likuai2010/auto-installer` 实证推翻：
> 安装可以走 **hdc 调试通道**（平行于权限系统），不需要 `INSTALL_BUNDLE`，用户在系统弹窗点一次
> 「始终允许使用本机调试」即可授权。本文其余部分作为能力边界参考仍有价值，但**第 0、2、4 节的结论已作废**。

---

本文档回答一个问题：**能不能在 HapStore 里做出「小白调试助手」那样的体验**，怎么做、哪些能做、哪些不可能。

---

## 0. 结论先行

1. **直接照搬做不到。** 小白调试助手是**安卓 App，跑在另一台设备上，作为「控制端」去连鸿蒙设备**；HapStore 是鸿蒙 App，**跑在被装的那台设备上**。角色是反的——它拥有的「安装能力」来自 ADB/hdc 的控制端身份，HapStore 天然没有。
2. **鸿蒙三方 App 拿不到安装权限。** `ohos.permission.INSTALL_BUNDLE` 是 `system_core` 级、`@ohos.bundle.installer` 是系统接口，第三方应用申请不到。这不是绕一绕能解决的问题。
3. **但体验可以完整复现，而且不用新增任何权限**——把「控制端」换成电脑浏览器：HapStore 在手机上起一个局域网 HTTP 服务，PC 浏览器打开就能拿到 HAP 文件和现成的 `hdc` 命令。华为官方就有「手机端用 TCPSocketServer 搭 HTTP 服务端给电脑浏览器访问」的范例，这条路是官方认可的能力。
4. 建议分两期：**先做本地 HAP 库（0.5–1 天，稳赚）**，**再做局域网伴侣模式（1.5–2 天，这是真正的杀手锏）**。

---

## 1. 小白调试助手到底是什么

先把它拆开，不然「集成类似功能」没法落地。

| 它做的事 | 本质 | 依赖什么 |
|---|---|---|
| 无线调试连接（IP + 端口 / 配对码） | 作为 **hdc/ADB 控制端**连上鸿蒙设备 | 另一台设备 + 调试协议 |
| HAP 一键推送安装 | `hdc install xxx.hap` | 控制端身份 |
| 批量安装、多设备 | 循环执行 install | 同上 |
| 本地 .hap 自动扫描 | 扫自己存储里的包 | 文件读取 |
| 卸载 / 备份 / 版本管理 | `bm uninstall` / 文件操作 | 控制端 + 文件 |
| 证书签名工具（p12 / csr / cer） | 生成密钥、申请证书 | 华为 AGC 账号体系 |
| 内置命令行终端 | 执行 hdc/adb 指令 | 控制端 |
| 调试日志、历史记录 | 抓 hilog、存操作记录 | shell 权限 + 本地存储 |
| 系统信息、调试开关引导 | 读设备信息 + 引导开开关 | 部分需权限 |

**一句话**：它的核心价值不是「界面好看」，而是**它站在设备外面，手里握着 hdc 的控制权**。这是 HapStore 作为被控端应用永远拿不到的东西。

## 2. 鸿蒙三方 App 的能力天花板（硬约束，附依据）

这部分决定了哪些功能连讨论的必要都没有。

| 能力 | 需要的权限 / 接口 | 权限等级 | 三方 App |
|---|---|---|---|
| 代码安装 / 卸载 HAP | `ohos.permission.INSTALL_BUNDLE` + `@ohos.bundle.installer` | **system_core**，且是**系统接口** | ❌ 不可能 |
| 查询已安装应用全量列表 | `GET_INSTALLED_BUNDLE_LIST` | **system_basic** | ❌ 不可能（华为官方明确回复：出于隐私不开放） |
| 查询指定应用信息 | `GET_BUNDLE_INFO` | normal | ⚠️ 名义上 normal，官方 FAQ 称实际只给系统应用，**待实测** |
| App 内直连本机 hdcd | RSA-4096 挑战响应鉴权，授权公钥存在 `/data/misc/hdc/hdc_keys` | 系统 | ❌ 不可能（无权限写该文件，首次连接还需用户点系统弹窗授权） |
| 读系统日志 hilog | shell 权限 | — | ❌ 不可能（沙箱隔离，只能读自己的） |
| 执行系统命令 | 无此 API | — | ❌ 不可能 |
| 本地生成有效签名证书 | 证书须由华为 AGC 签发 | — | ❌ 不可能 |
| **起本地 TCP / HTTP 服务** | `INTERNET`（**已有**） | normal | ✅ **可行，华为官方有完整范例** |
| **拿本机 IP** | `GET_NETWORK_INFO`（**已有**） | normal | ✅ 可行 |
| **读写自己沙箱文件** | 无 | — | ✅ 可行 |
| **经用户授权读公共目录** | `filePicker` | 无需权限 | ✅ 可行 |

**关键推论**：你现在对外宣传的「只申请 INTERNET 和 GET_NETWORK_INFO 两个权限」——本方案**一个权限都不用加**。这条要保住，它是 HapStore 的信任资产。

## 3. 逐项可行性矩阵

| 小白调试助手的能力 | HapStore 能做吗 | 变成什么形态 |
|---|---|---|
| 无线调试连接 | ⚠️ 变形可行 | 不做「控制端」，做「**被控端信息面板**」：显示本机 IP、引导开无线调试、让你填端口、生成 `hdc` 命令和二维码 |
| HAP 一键推送安装 | ❌ 不可能 | 改为「**电脑上一键执行**」，HapStore 负责把包和命令送到电脑 |
| 批量安装 | ⚠️ 变形可行 | 生成批量 `hdc install` 脚本，电脑端一次跑完——比逐个点更快 |
| 本地 .hap 扫描 | ✅ 可行 | 扫自己下载目录 + filePicker 授权扫公共目录，做成「本地 HAP 库」 |
| 卸载应用 | ❌ 不可能 | 无替代，明确不做 |
| 备份 / 版本管理 | ✅ 可行 | HAP 文件本身的管理：去重、按版本排列、导出、清理 |
| 证书签名工具 | ❌ 不可能 | 降级为「**签名有效期提醒**」（未实名 14 天 / 实名 180 天，到期提醒重装） |
| 命令行终端 | ❌ 不可能 | 降级为「**命令生成器**」：拼好命令，一键复制 |
| 调试日志 | ⚠️ 部分可行 | 只能自己的应用日志（`HLog` 已有），做成「导出日志供提 issue」——实用且干净 |
| 系统信息 / 调试开关引导 | ⚠️ 部分可行 | `deviceInfo` 部分字段受限；跳转开发者选项设置页**大概率可行，待实测** |

## 4. 三条路线，选哪条

### 路线 C：App 内自建 hdc 客户端 —— ❌ 否决

想法：用 `@ohos.net.socket` 连本机 hdcd（无线调试端口），直接下 install 命令。
否决理由：hdc 是 **RSA-4096 挑战-响应鉴权**，设备端只认 `/data/misc/hdc/hdc_keys` 里已授权的公钥；App 写不进这个文件，首次连接还要用户在系统弹窗点「允许」——手机上没法给自己授权。这条路是死路，别浪费时间。

### 路线 B：本地 HAP 库 + 安装引导增强 —— ✅ 打底

完全可行，无风险，工作量小。

- **本地 HAP 库**：把下载过的 HAP 管起来——按应用归组、版本号、体积、下载时间；支持删除释放空间、导出到公共目录、按版本去重。
- **安装引导升级**：现在的 `InstallGuidePage` 是静态图文；改成**可勾选清单**（开发者模式 → 无线调试 → 记录 IP:端口 → hdc 命令），填了 IP/端口就自动生成可直接复制的命令。
- **自身日志导出**：把 `HLog` 攒的日志导出成文件，用户提 issue 时直接附上。

### 路线 A：局域网伴侣模式（推荐，真正的杀手锏）—— ✅ 增值

**核心思路**：HapStore 在手机上起一个局域网 HTTP 服务，电脑浏览器打开就拿到一切。

完整闭环：

```
手机：装 HapStore → 浏览选应用 → 开启无线调试（拿到 IP:端口）
      → 点「启动电脑伴侣」，显示 http://192.168.1.40:8080
电脑：浏览器打开该地址 → 看到应用清单 + HAP 下载链接 + 现成 hdc 命令
      → 下载 HAP → 复制命令 → hdc tconn → hdc install
```

**为什么这条路成立**：
- 华为官方 architecture-guides 里就有「手机端用 `TCPSocketServer` 搭 HTTP 服务端供电脑浏览器访问」的完整范例，属于公开能力。
- PC 端执行 `hdc install xxx.hap` 时，**HAP 在 PC 本地即可**，hdc 自己会把包传过去。所以不需要文件留在手机上，闭环天然成立。
- 只要 `INTERNET` 权限，你现在就有。

**网页端提供什么**：
- `GET /` — 应用清单页：已下载 / 全部，带 HAP 下载链接
- `GET /f/<id>` — 下载单个 HAP
- `GET /install.sh`（或 `.bat`）— **批量安装脚本**，自动 tconn + 逐个 install，双击即跑
- 页面上直接给「一键复制全部命令」

**这比小白调试助手还顺**：不用在另一台安卓手机上装 App，浏览器就行；批量安装天然支持；HAP 不用手动翻目录。

**约束（必须如实告知用户）**：
- 需要一台装了 hdc 的电脑（DevEco Studio 或 Command Line Tools）。
- 无线调试端口是**系统动态分配的**（如 `192.168.1.40:41335`），HapStore 读不到，必须用户手填一次。这是硬限制。
- 华为官方文档标注「TCP 调试功能尚未稳定」。
- 路由器开了 AP 隔离会导致 PC 访问不到，页面要明确提示排查。

### 推荐组合：**B 打底 + A 增值**，分两期发

## 5. 落地设计（路线 A + B）

### 5.1 新增文件

```
app/entry/src/main/ets/
  service/
    LocalServer.ets        TCPSocketServer + 极简 HTTP（GET /、/f/<id>、/install.sh）
    LocalHapLibrary.ets    本地 HAP 库：扫描、归组、去重、删除、导出
    DebugCommand.ets       命令/脚本生成（tconn + install，单条与批量）
    LogExporter.ets        自身日志导出
  pages/
    DebugHubPage.ets       「调试助手」页：本机信息 / 启动伴侣 / HAP 库 / 引导清单
```

### 5.2 服务开关与生命周期（安全红线）

- **默认关闭**，只在用户点「启动」时监听。
- 页面 `aboutToDisappear` / App 退后台时**必须关闭**，不留常驻端口。
- 页面上显式写明：仅局域网可访问、用完请关闭。
- 端口默认 8080，被占用则递增重试（8081…8090）。

### 5.3 需要新增权限吗

**不需要。** `INTERNET`（起 TCP 服务）+ `GET_NETWORK_INFO`（拿本机 IP）两个权限已在 `module.json5` 里。README 里「只申请两个权限」的说法可以原样保留。

### 5.4 Tab 位置

当前是「应用 / 下载 / 更新 / 设置」四 Tab。建议做成第五个 Tab「**装机**」，或先挂在设置页里做入口、验证后再提级。

## 6. 必须先验证的未知项（半天 spike）

路线 A 生死取决于这几条，先验证再动手写代码：

1. **真机上 `TCPSocketServer` 能否 bind `0.0.0.0:8080` 且被同局域网 PC 访问到**（官方范例是 API 10，需在你的目标 API 上验）。
2. **App 退后台 / 锁屏后 socket 是否存活**——大概率会被挂起；对策是页面常亮提示「请保持此页打开」，或申请短期后台任务。
3. **`connection.getDefaultNet().getConnectionProperties()` 能否拿到 IPv4**——拿不到就没有 IP 可显示。
4. **跳转「开发者选项 / 无线调试」设置页的 want 是否可用**（`com.huawei.hmos.settings` + 对应 uri）——社区说法不一，需实测；不可用就退回图文引导。
5. **`filePicker` 能否按 `.hap` 后缀过滤**——影响本地 HAP 库扫公共目录的体验。
6. **`GET_BUNDLE_INFO` 在真机上三方应用是否真能调用**——能调用就能做「某应用是否已安装」的单项检测（不是全量列表），这是个小惊喜。

## 7. 工作量与排期建议

| 阶段 | 内容 | 预估 |
|---|---|---|
| Spike | 上表 6 项验证，出一份「可行 / 不可行 + 备选」结论 | 0.5 天 |
| 一期（B） | 本地 HAP 库 + 安装引导升级 + 日志导出 | 0.5–1 天 |
| 二期（A） | 局域网伴侣服务 + 网页端 + 批量脚本生成 | 1.5–2 天 |
| 联调 | 真机 + PC 端到端跑通，含失败分支 | 0.5 天 |

**合计约 3 天**（含 spike）。建议先只做 spike + 一期，验证用户反馈后再投二期。

## 8. 风险提示

- **别承诺「一键安装」。** 鸿蒙不允许三方应用静默安装，这是系统规则。宣传上必须守住「发现 → 下载 → 交给系统/hdc」的定位，否则预期管理会翻车。
- **起局域网服务要做得克制。** 默认关闭、用完即关、页面明写范围。这是唯一需要谨慎对待的新增能力。
- **端口动态分配是体验短板。** 每次开无线调试端口都变，用户得重填。可在 App 里缓存上次填过的端口并标注时间，减少重复输入。
